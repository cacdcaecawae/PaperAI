# Agent Note: 按学校成套的模板，每种文档类型一份格式

Status: implemented

[English](2026-09-03-paperai-template-model.md) | 中文

## 问题

PaperAI 随产品提供一所学校的 Word 模板（HIT 硕士套装含开题报告表单、中期报告表单和一份学位论文书写范例），并允许用户添加自己的模板。最初的客户端把每个模板文件当作平级的目录条目，要求用户为每份文档挑选一个：先在项目下的侧边栏里挑，再在模板标签页里挑一次。模板因此显得像项目层级中的一层而不是配置，而且每次新建文档都在重复学校早已做出的选择。每次导入都会询问文档角色，无论模板是否会被套用。用户的结论是这套安排读不懂：模板应该放在设置里，项目选一套，文档的种类决定其余的事。

## 决策

一套模板（template）是一所学校完整的论文格式套装，每种文档类型（document type）至多含一份格式（format）：开题报告、中期报告、学位论文、结题材料或其他。套装存放在设置中的全局模板库（template library）里，内置的 HIT 套装与用户创建的自定义套装并列，不属于任何项目。[术语表](../../../../CONTEXT.md)定义这些术语；[界面重构记录](../feature/2026-09-03-paperai-ui-overhaul.zh.md)记录建在这套模型之上的各个界面。

一个项目选用一套模板或不用模板，这个选择是一项被记录的决定：`ProjectRecord.templatePackId` 指明套装，`templateDecidedAt` 记录用户作答的时间（包括"不用"这个答案），因此起始页对未决定的项目每次访问只问一次，对已决定的项目从不再问。之后选择或更换套装不会改动已有文档。

文档类型决定格式。从项目套装新建的文档带有用户所选的类型（"新建开题报告"新建的是开题报告），其初始版本绑定该类型的格式。自由导入不询问类型：文档类型为 `other`，不带格式。只有在套用格式时才询问类型：Host 先根据标题、再根据开头段落猜测，用户确认或另选，绑定作为一个版本落地，携带 `set-document-type`（类型变化时）和 `bind-template`。用户可以通过另选类型重新绑定，或解除格式（`unbind-template`）；Agent 通过 `paperai_commit_document` 的 `set-document-type` 变更做同样的事；类型变化会解除已绑定的格式，除非同一次提交绑定了另一份，而把类型设为文档已有的类型会被拒绝。

自定义套装通过按文档类型逐个添加 Word 文件及其用途构建：表单模板即文档本身，排版参考约束用户上传的初稿。自定义套装持久化在 `<storageRoot>/library/library.json`，文件存放在模板资源存储中；内置套装来自随产品提供的模板包清单。自定义套装在仍被项目引用时也可以删除：这些项目会显示模板缺失，直到重新选择，文档则保留已绑定的格式。

## 考虑过的替代方案

**把模板作为侧边栏层级中的一层。** 否决：模板是配置，不是某个项目的内容；把它和文档、会话并列正是侧边栏读不懂的原因。

**从平铺目录中为每份文档挑选模板文件。** 否决：学校的套装已经把每个文件与一种文档类型配对，按文档挑选是在重复套装已经编码的决定；项目级选择让挑选自动完成，并保证一个项目只对应一所学校。

**在导入时询问文档类型。** 否决：自由写作不应被盘问，类型只在套用格式时才有意义；在套用时询问并附上 Host 的猜测供确认，可以让导入保持一步完成。

**在创建项目时选择模板。** 否决：创建项目就是选择一个文件夹，有些项目从不使用模板；每次访问只问一次的对话框在答案有意义时才提问，而"不用"是一个有效且被记录的答案。

**只按文档绑定，不设项目级选择。** 否决：每份新文档都要再问一次用哪所学校的格式，起始页也无法提供按类型的新建操作。

## 后果

模板选择是项目状态，格式绑定是文档状态，两者各自演化：更换项目套装不会改写文档，项目放弃套装时文档仍保留其格式。"不用"是一等决定，因此领域层区分未决定的项目与无模板的项目。一套模板每种类型只含一份格式，因此有两种开题报告变体的学校需要两套模板。每次类型变化都是一个版本，账本因而显示谁在何时改变了文档的类型。猜测出的类型只是建议；绑定始终等待人或 Agent 提交。
