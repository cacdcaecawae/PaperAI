# Agent Note: PaperAI 项目初始化要求明确操作

Status: implemented

[English](2026-09-26-paperai-explicit-project-initialization.md) | 中文

## Problem

PaperAI 共享 DSH 的工作区注册表。工作区记录代表导航目标，不代表允许向其中写入 PaperAI 目录、Git 元数据或 Agent 指令。通过浏览器订阅或读取操作初始化项目会改动无关仓库，还可能重新创建已经移动的目录。

## Decision

[工作台服务](../../../../packages/paperai/workbench-service/README.zh.md) 负责浏览器操作的初始化。选择项目模板（包括不用模板）、导入文档或从模板新建文档可以初始化尚未登记的项目。这些操作首先要求工作区根路径是已存在的目录。已存在的项目直接复用，不再次运行目录和章程准备。

共享 API 网关同样要求指定工作区的 `session.create` 请求具有已存在的目录。启动时自动选择会话不能通过会话初始化重新创建已删除的工作区。

读取概览和打开文档从不创建项目。未登记的工作区具有只读概览，包含工作区标题、尚未决定的模板和空文档列表。现有起始页控件允许用户选择模板或导入文档。打开文档及项目诊断要求项目已经存在。浏览器只为已挂载的视图请求概览，不初始化整个工作区列表。

## Alternatives considered

**只删除启动订阅。** 已挂载视图和直接 Remote 调用仍然会读取概览，因此 UI 的触发时机不能授权文件系统修改。

**分离工作区注册表或增加初始化标记。** 保证读取安全不需要这两种机制。共享注册表仍然方便导航，现有明确的文档和模板操作已经表达所需意图，无需另一份持久化状态。

## Consequences

仅选择或查看目录不会安装 PaperAI 指令。目录不存在时会报错，目录保持缺失状态。已有项目和无关 DSH 工作区可以共存于同一列表。已经写入的项目文件不会自动删除，因为其中可能包含用户修改。

验证覆盖只读 Remote 调用、明确初始化、缺失及非目录根路径、项目根路径不一致，以及无关工作区的浏览器启动和视图挂载。无密钥浏览器快照记录明确选择模板前后可用的模板和导入控件。
