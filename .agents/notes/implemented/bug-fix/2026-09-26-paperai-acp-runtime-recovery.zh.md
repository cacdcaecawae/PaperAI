# Agent Note: PaperAI ACP 运行时恢复保留已确认设置

Status: implemented

[English](2026-09-26-paperai-acp-runtime-recovery.md) | 中文

## 问题

提供方进程可能在没有取消或选择失败的情况下退出。复用已断开的运行时会使提示词和模型操作都无法恢复。新进程加载同一会话时也可能声明默认设置，因此在恢复会话选择前记录启动元数据会丢失思考级别、开关和通用选项。

## 决策

显式要求替换或当前传输断开时，都必须替换运行时。提示词和串行模型操作队列使用同一判断。恢复会关闭旧进程并加载所属提供方会话；加载失败时保留现有历史，仍可重试。替换只在发布后进行：发布前提供方链接与选择仍处于待提交状态而尚未写入日志，因此需要用到启动期间丢失的运行时的启动步骤会使启动失败，启动会回滚，并可用同一 Session ID 重试。启动未察觉的丢失则在发布后像其他断开一样恢复。启动失败且没有剩余运行时时，诊断仍能报告会话已断开。

每次启动都会读取该提供方最后确认的 `paperai/acp/config`，按模型、思考级别、开关、通用选项的顺序恢复。权限控件继续由 Session 沙箱预设管理。启动配置通知只更新运行时状态，不发布中间选择；Agent 只记录最终生效的设置。缺失或安全回滚后遭拒的偏好会告警，并保留提供方接受的值。连接丢失、取消或选择回滚失败会使恢复失败。启动设置固定于已发布的会话。

这明确了[模型选择](../feature/2026-09-02-acp-model-effort-switch-selection.zh.md)的替换配置行为，并保留[提供方取消结算](2026-09-01-paperai-acp-cancellation-settlement.zh.md)规则。

## 曾考虑的替代方案

仅在进程退出回调中标记重启会遗漏其他传输断开，以及恢复失败后没有剩余运行时的情况。重放当前内存选择可能保留部分失败的事务。重放渠道默认值会用新会话偏好替换当前会话的选择。发布前恢复需要从待提交的链接与选择而非日志恢复；让启动失败更简单，且本就可以重试。

## 后果

恢复可能在提示词或模型操作前增加配置 RPC。提供方不再支持的值无法保留，但日志会记录实际回退选择。恢复由下一个操作触发；失败的提示词不会自动重放。失败即关闭存在一条死路：提供方拒绝某个已保存的值且回滚该更改也失败时，每次恢复都会以同样方式失败，而模型与选项更改要等恢复完成才执行，用户无法改选其他值。该会话会一直不可用，直到提供方接受已保存的值或完成回滚，例如提供方修复问题或适配器更新之后；其对话记录仍可阅读，立即继续的唯一办法是新建会话。子进程回归覆盖冷启动恢复、取消回合、发布前后的崩溃、重试及设置遭拒。无密钥快照启动实际 PaperAI 档案，捕获跨崩溃与取消后的选择及对话记录。
