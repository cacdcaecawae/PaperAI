# Agent Note: 保留 Word 元数据与原始编辑目标

Status: implemented

[English](2026-09-13-paperai-word-edit-preservation.md) | 中文

## 问题

根据浏览器可编辑字段重建段落会丢失预览无法表达的 Word 属性。改为拒绝这些属性又会阻止普通中文模板编辑，包括带东亚字体提示的 run。位置地址可能在前面的结构修改后指向新插入段落，而提交记录仍声称修改另一个语义节点。每次替换前都读取并解析全文，会增加多段保存的延迟。

## 决策

OfficeCLI Provider 在既有文件 lease 内读取一次文档 XML，先将全部原始 Office 路径绑定到 XML 节点，再按调用方顺序修改。插入和拆段后引用仍附着于原节点；使用已删除节点会在写入前拒绝整个批次。工作台、直接服务和 MCP 调用共用此规则，不依赖排序或 `paraId` 是否存在。

字符差异为存留文字复用原 run 属性。插入文字继承相邻属性，替换文字继承被替换范围的起点，空段保留字符属性种子。显式格式覆盖已表达的字段，省略字段保留元数据。[格式意图决策](2026-09-13-paperai-rendered-format-intent.zh.md)拥有浏览器读数转为显式覆盖的规则。书签和分页标记保留相对文字的位置；拆段继承布局，分节属性保留在最后一个替换段落。尚不支持编辑的对象仍拒绝替换。

私有 JSON 文件承载一次 OfficeCLI `batch --input` 命令，通过 `/word/document.xml` 替换正文，再执行保存。批次汇总与单项结果必须确认操作成功执行，不能仅凭进程退出码为零就发布版本。写入别名 `/document` 不适用：它的类型化解析器会重命名旧缩进属性，改变双向文字段落的物理边缘。标准包部件保留这些属性和未修改子树。命令文件避免 Windows 参数长度限制，并在成功或失败后删除。显式样式变更通过额外一次样式读取解析名称。

段落样式菜单经引擎、文档服务和工作台快照读取文档定义的 ID 与显示名称，并提交存储 ID，精确 ID 优先于同名样式。可选样式部件缺失时没有可选项，样式内容损坏仍使引擎读取失败。工作台目录读取失败时返回空目录并禁用菜单，不阻止打开文档，也不影响已完成的提交。延迟提交回执在刷新前保留浏览器原目录。预览不标识各段落当前样式，因此没有草稿选择时菜单显示“应用样式”。

本决策部分取代[字符格式](../feature/2026-09-10-paperai-character-formatting.zh.md)的引擎重建与 run 继承，以及[写作流程](../feature/2026-09-12-paperai-writing-workflow.zh.md)的寻址和保护选择。它们的浏览器交互、传输校验、草稿与事务决策继续有效。解析后的 XML 是候选 DOCX 在单次操作内的投影，没有持久化或浏览器拥有的第二份权威文档。

## 考虑过的替代方案

**在重建白名单中允许更多 run 属性。** 这能恢复输入，但 run 拆分或合并时仍会丢失元数据。

**将所有调用方的修改逆序排列。** 通用批次的插入、删除和重复引用具有实际顺序语义。绑定原节点保留此顺序，也保护其他调用入口。

**每次结构操作后重新读取。** 重复解析增加延迟，且仍需跟踪原身份。一次绑定的投影同时满足两项要求，无需长期缓存。

## 测试

单元测试验证元数据映射、空段继承、显式清除、标记、分节顺序、原节点引用、文件清理，以及每批只读取一次文档。Windows CI 的原生测试要求 OfficeCLI 1.0.145，编辑真实 HIT 开题报告模板，比较未修改 XML 子树，检查双向文字的旧缩进属性，并验证常驻与重新打开后的文字。真实直接服务及 SDK 到 MCP 读回覆盖有无段落 id、混合操作和已发布版本内容。组装后的浏览器场景验证编辑及延迟的 Agent 模型替换。

## 后果

多个修改块共享一次文档读取和文件承载的写入。工具栏以外的 Word 属性会保留，但不因此新增控件。目标段落内的绘图、公式、域和符号编辑仍需使用 Word。草稿持久化和 Word 最终分页不在本次变更范围内。
