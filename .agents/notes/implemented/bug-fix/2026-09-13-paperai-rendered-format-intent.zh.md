# Agent Note: 区分预览格式与 Word 修改意图

Status: implemented

[English](2026-09-13-paperai-rendered-format-intent.md) | 中文

## 问题

OfficeCLI 的 HTML 可能显示与 Word run 存储属性不同的回退字体。只含 `w:hAnsi="宋体"` 的 run 可以显示为 Times New Roman。修改文字或加粗时若提交这个未变化的显示值，就会静默覆盖原字体。浏览器解析出的样式描述的是预览，不是改写 Word 元数据的请求。

## 决策

浏览器草稿保留完整渲染 run 供重绘与撤销，同时保留初始及当前字符读数。提交时比较这些读数，只发送改变的字符属性。普通输入不重述初始字体或字号，单独加粗也不重述无关字段。清除属性使渲染值改变时，仍显式提交清除后的值。选择已显示的值视为无操作，不表示规范化隐藏的 Word 属性。

字符对齐采用与 Word 引擎相同的插入和替换继承规则：插入文字继承相邻原文字，替换文字从被替换范围的起点继承。空段保留格式基准。首部拆分出的空段继承第一个原始 run，包括字体槽位及预览未表达的其他属性。拆分出的空段在首次插入和草稿重绘时，都在带格式的 span 内保留占位换行，使原生输入继续采用该格式；占位符不计入文字。拆段保持原始块归属与显式段落布局，作为分隔符的换行不进入 run 文字。渲染基准只存在于浏览器状态中，不进入修改 RPC。

本决策部分取代[字符格式](../feature/2026-09-10-paperai-character-formatting.zh.md)中的草稿序列化；该记录的选区编辑与传输校验继续有效。[Word 编辑保留](2026-09-13-paperai-word-edit-preservation.zh.md)仍拥有原始 XML 属性、字符继承及事务化引擎写入。

## 考虑过的替代方案

**传输全部解析样式。** 即使用户只改文字，浏览器回退值也会成为破坏性的覆盖。

**从所有请求中删除字体和字号。** 这能保护初始属性，却也阻止用户主动修改字体和字号。

**将重复选择相同值视为元数据规范化。** 菜单描述可见值；未改变的选择不表示要替换各文字体系的 Word 属性。

## 测试

浏览器单元测试覆盖未改变的渲染字体、独立格式修改、清除、混合 run、插入、空段、拆段、撤销和草稿重绘。组件到控制器的测试检查提交请求，组装浏览器测试验证原生输入与保存后的 Word XML。原生 OfficeCLI 1.0.145 测试修改只有 `hAnsi` 字体的 run 文字并加粗，在关闭及重新打开后验证字体、字号和其他属性保留。

## 后果

预览显示的格式继续服务编辑，但不成为第二份文档权威。浏览器本地草稿比提交的修改包含更多显示信息。预览以外的 Word 属性仍由引擎负责，工具栏不提供规范化这些属性的命令。
