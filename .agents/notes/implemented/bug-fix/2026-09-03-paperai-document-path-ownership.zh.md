# Agent Note: PaperAI 文档路径保留持久归属

Status: implemented

[English](2026-09-03-paperai-document-path-ownership.md) | 中文

## 问题

项目说明将 Word 文档放在公开的项目目录中，导入实现却发布到隐藏的应用数据目录。文件名分配仅检查磁盘文件。文件被移除后，文档记录仍然存在，后续导入便可能为第二份文档分配相同路径。

## 决策

新导入将不可变原件发布到 `documents/source`，将可编辑 DOCX 发布到 `documents/working`。导入暂存和版本快照保留在 `.paperai` 中。已有文档按记录中的路径读取；打开项目不会移动其文件。

发布时除了检查现有文件，还会保留全部受管文档经过 Unicode 规范化、不区分大小写的名称。文件缺失不会释放持久文档的名称。互斥文件发布仍负责协调并发导入。文件名后缀为新文档分配独立名称，避免复用旧文档缺失的路径。

## 曾考虑的替代方案

**将用户文档保留在隐藏的应用数据目录。** 这与项目说明矛盾，也让普通 Word 文件难以查找。

**只依据现有文件分配名称。** 文件缺失不代表文档记录已删除。复用路径会让两个文档身份读取同一文件。

**文件消失时删除记录。** 暂时不可用就会丢弃文档身份及其历史引用，缺少用户决定。

## 后果

新项目在文档说明的位置提供 Word 文件。已有记录和路径继续有效，缺失文档保留元数据以供明确恢复。导入回归覆盖原件和工作副本同时缺失的情况；组装后的新建项目场景选择模板、创建一份文档并检查其公开工作路径。
