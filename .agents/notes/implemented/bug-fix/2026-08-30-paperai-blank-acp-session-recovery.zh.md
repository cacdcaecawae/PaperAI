# Agent Note: PaperAI 只替换无法恢复的空白 ACP 会话

Status: implemented

[English](2026-08-30-paperai-blank-acp-session-recovery.md) | 中文

## 问题

ACP（Agent Client Protocol）适配器可能在提供方持久化任何对话之前返回提供方会话 id。Codex 新建 `thread` 后未收到提示词时会出现这一生命周期：PaperAI 已经记录成功的 `session/new` 关联，但后续进程无法加载该 id。权限变更、模型发现等冷启动操作会在 agent（智能体）恢复期间失败，即使 DSH 会话中没有需要恢复的对话。

把所有加载失败都视为可替换并不安全。DSH 会话中只要存在已记录的用户消息或已开启的轮次，就可能对应 PaperAI 没有复制的提供方历史。替换提供方会话会导致用户可见的 DSH transcript（文本记录）与提供方的提示词上下文不一致。

## 决策

只有 DSH 事件日志既不包含 `user/message` 也不包含 `turn/start` 时，`AcpAgent` 才会把提供方会话归类为可替换。运行时仍会先尝试 `session/load`。如果该请求失败、调用方信号仍有效且会话可替换，运行时就会清除失败的回放状态，在同一 ACP 连接上新建提供方会话，重新应用当前原生权限模式，并发布新的 `paperai/acp/session` 关联。

只要 DSH 会话中存在用户或轮次历史，加载失败就会继续明确终止恢复。取消操作同样会明确终止，而不会进入替换路径。该规则依赖 DSH 持有的持久事件，而不是提供方错误文本，因为 ACP 适配器可能把缺失或未持久化的提供方 `thread` 统一表示为普通内部错误。

## 验证

真实 `codex-acp` 适配器测试会创建空白 `thread`，让测试用 Codex App Server 拒绝后续恢复，并验证 PaperAI 新建第二个 `thread`，且该 `thread` 采用要求的原生权限模式。agent 生命周期测试验证持久空白 DSH 会话会记录新关联，并验证存在 `turn/start` 事件后，相同加载失败绝不会进入 `session/new`。

## 曾考虑的替代方案

**每次加载失败后都替换提供方会话。** 这样虽然能恢复操作控件，却可能静默丢弃提供方对话历史。替换路径仅适用于 DSH 日志已经证明没有用户消息或轮次开始的情况。

**绝不替换已记录的提供方会话。** 即使 `session/new` 成功返回，空白提供方 id 也不一定已经持久化。永久失败会让原本为空的 DSH 会话无法使用，却没有保留任何额外上下文。

**匹配提供方特有的会话缺失诊断。** Codex 目前把这种情况报告为普通内部错误，其他适配器也可能使用不同文本。DSH 事件历史能够提供安全条件，提供方措辞不能。

## 后果

空白 Codex 会话可以在 Host 或 ACP 进程重启后继续使用，并可执行权限变更、模型发现以及第一次提示词。提供方状态无法恢复时，已有对话历史的会话会继续明确失败，确保 PaperAI 不会把全新的提供方上下文显示为既有工作的延续。
