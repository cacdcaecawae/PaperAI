# Agent Note: PaperAI 工作台临时状态跟随其所属 revision

Status: implemented

[English](2026-08-29-paperai-transient-state-lifetimes.md) | 中文

## 问题

PaperAI 保存两类非持久工作台状态：浏览器中的选中节点草稿，以及 Host 中最近一次模板门禁报告。两者都必须继续归属于产生它们的文档 revision。

外部更新横幅允许新提交的文档投影替换仍有修改的浏览器草稿。保留草稿避免了数据丢失，但同一节点发生外部修改时，不可变 buffer 仍停留在旧 revision：再次加载会重复冲突，提交会因基线过期而被拒绝，关闭横幅也不会建立新基线。与此同时，每份文档只保留一份门禁报告虽然消除了随 revision 增长的问题，却没有对并发生产者排序。revision R1 的延迟验证可以覆盖较晚完成并缓存的 R2 导出报告，导致当前投影找不到匹配门禁。

## 决策

加载外部文档版本时保留选中节点的 dirty 草稿。控制器会从新 head 读取同一节点：如果 Host 文本仍与草稿的原始基线一致，则把不可变 buffer 更新到新 revision，并重新应用浏览器本地草稿。同一节点发生变化时，控制器仍会把文档和不可变节点 buffer 推进到外部 head，同时把本地草稿和外部文本保留为明确的冲突输入，并在用户采用本地文本、采用外部文本或采用当前编辑的合并文本之前禁止文档操作。本地与合并方案会相对最新外部基线保持 dirty，并可正常提交；外部方案选择已经持久化的 head 文本，因此恢复为 clean。重新加载会消费请求开始时捕获的准确外部通知，即使权威打开结果已经进一步推进；加载期间收到的新通知仍会保留。合并期间再次出现外部 head 时，当前合并草稿仍会保留，并通过同一条可取消路径再次重基。工作台没有本地修改时，外部提交仍会自动加载。

Host 门禁缓存为每份文档最多保留一个槽位。每次验证或导出都会记录唯一所有权标识及其开始时的 revision。revision 未变化时，只有最新标识可以发布结果。成功导出推进来源 revision 后，可以取代仍从同一来源发起的较晚标识，因为它的报告属于新里程碑；从该里程碑 revision 发起的门禁操作仍会阻止正在完成的导出。导出的里程碑也必须仍是当前 head。提交、恢复或模板关联发布目标 revision 后，后续流程只会在活动槽位仍属于旧来源 revision 时写入锚定目标的修改屏障。这样既能阻止旧工作重新填充槽位，也不会覆盖从已经发布的目标 revision 发起的验证。

## 曾考虑的替代方案

**显示信息警告后仍允许破坏性加载。** 未提交草稿没有可恢复版本，因此警告无法防止数据丢失。

**要求先提交或放弃再加载。** 其他 Session 推进文档后，旧 head 上的提交会被拒绝，因此该指引并没有提供保留草稿的成功路径。节点级 rebase 可以直接处理不冲突的情况，并在冲突时保留双方内容。

**显示两份冲突文本，但继续使用旧 revision。** 用户虽然能比较输入，生成的提交仍会携带过期基线。冲突解决必须先把浏览器 buffer 绑定到最新的不可变节点版本。

**保留每个 revision 的门禁报告。** 工作台只暴露当前文档投影，持久提交历史也不消费门禁缓存条目。历史保留需要独立的持久数据模型，而不是无限增长的进程内 Map。

**只要 revision 一致就接受完成结果。** 受阻导出与连续验证可能在同一 revision 上竞争。仅比较 revision 无法阻止较早操作覆盖较晚的用户可见结果。

## 验证

控制器测试覆盖节点未变化时的重基、本地、外部和合并三种同节点解决方案、基于最新版本的提交请求、合并期间再次出现外部 head、节点读取取消、较新权威打开结果消费旧通知，以及加载期间保留新通知。组件测试展示两份保留文本和三个本地化操作，并在冲突未解决时禁止所有相关文档操作。Keyless 浏览器场景会导入真实 Working DOCX、通过 Host 创建外部提交、快照记录冲突界面、合并文本并成功提交。工作台服务的 deferred 测试会让验证和导出 Promise 在成功导出、受阻导出、新 revision 验证以及外部推进 head 的场景中双向乱序完成；另外三条 deferred 测试会在提交、恢复和模板关联已经发布目标 revision、但修改 Promise 尚未完成时启动验证。当前报告始终属于其来源 revision，并且缓存每份文档最多保留一个槽位。

## 后果

不冲突的外部提交可以推进当前文档，而不会中断本地编辑。同一节点发生冲突时会保留双方输入、把编辑状态重基到最新 head，并提供可以继续提交的解决路径，无需手工复制、放弃和粘贴。门禁报告占用的内存仍按文档数量有界，不随 revision 或操作次数增长；延迟工作也无法替换较新操作或修改所选择的报告。
