# Agent Note: PaperAI 工作台临时状态跟随其所属 revision

Status: implemented

[English](2026-08-29-paperai-transient-state-lifetimes.md) | 中文

## 问题

PaperAI 保存两类非持久工作台状态：浏览器中的选中节点草稿，以及 Host 中最近一次模板门禁报告。两者都必须继续归属于产生它们的文档 revision。

外部更新横幅允许新提交的文档投影替换仍有修改的浏览器草稿。按钮虽然表示加载新版本，却没有要求用户先提交或放弃尚未形成版本的草稿。与此同时，每次成功导出都会创建一个里程碑 revision，并按该 revision 缓存门禁报告，却不删除前一个 revision 的条目。重复导出因此会保留任何调用方都无法再读取的报告。

## 决策

加载外部文档版本时保留选中节点的 dirty 草稿。Controller 会从新 head 读取同一节点：如果 Host 文本仍与草稿的原始基线一致，则把不可变 buffer 更新到新 revision，并重新应用浏览器本地草稿；如果该节点已经变化或消失，则保留旧投影和草稿并报告冲突。工作台没有本地修改时，外部提交仍会自动加载。

Host 门禁缓存为每份文档保留一个条目。每个条目保存 revision 与报告；只有当前文档 revision 一致时才投影报告。验证、被阻止的正式交付和成功导出会替换该文档的条目，文档修改则删除它。

## 曾考虑的替代方案

**显示信息警告后仍允许破坏性加载。** 未提交草稿没有可恢复版本，因此警告无法防止数据丢失。

**要求先提交或放弃再加载。** 其他 Session 推进文档后，旧 head 上的提交会被拒绝，因此该指引并没有提供保留草稿的成功路径。节点级 rebase 可以直接处理不冲突的情况，并在冲突时保留双方内容。

**保留每个 revision 的门禁报告。** 工作台只暴露当前文档投影，持久提交历史也不消费门禁缓存条目。历史保留需要独立的持久数据模型，而不是无限增长的进程内 Map。

## 验证

Controller 与组件测试证明：dirty 状态下加载外部版本会在节点未变化时更新基线但不修改草稿；同一节点发生外部变化时，则保留旧投影和草稿。工作台服务导出测试连续创建两个导出里程碑，并确认该文档最终只保留一个门禁缓存条目。

## 后果

不冲突的外部提交可以推进当前文档，而不会中断本地编辑。同一节点发生冲突时会保持显式状态，并保留本地草稿，直到用户解决或放弃。门禁报告占用的内存上限由 Host 观察过的文档数量决定，不再随 revision 或导出次数增长。
