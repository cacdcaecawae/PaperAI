# Agent Note: Multi-agent thesis writing baseline

Status: implemented

English | [中文](2026-09-02-multi-agent-thesis-writing-baseline.zh.md)

> Templateless free mode, the writing charter, the gate digest, the native document tools, and the access scope remain current. The template-first sidebar start flow, the tabbed workbench with its status bar, the pine-green `ctx.theme.overrideTokens` layer, and the consequence that the hero copy had no override seam are superseded by [the PaperAI UI overhaul](2026-09-03-paperai-ui-overhaul.md); the template model behind the new start flow is [the PaperAI template model](../architecture/2026-09-03-paperai-template-model.md).

## Problem

PaperAI's product direction is several peer agents — the built-in DSH agent, Codex, and Claude — writing one thesis under one version ledger, but four gaps blocked that parity. A document without a template was forced into a `template_missing` hard error that blocked formal delivery, so templateless free writing was impossible. No channel carried a writing workflow to the external CLIs: ACP cannot inject a system prompt, and nothing told Codex or Claude to read template contracts or fix gate findings. Commit results carried the stored gate report only as an unlabeled field no model was told to read. And the built-in DSH agent had no document capability at all — the ten PaperAI MCP tools were issued only to ACP sessions behind a `codex`/`claude` actor whitelist, so the shipped `standard` preset could not touch a Working DOCX.

## Decision

Four shipped pieces close the loop, one charter source and one gate digest shared by every route.

**Templateless free mode.** `checkTemplateContract` returns a passing report with no findings when no template is attached (`packages/paperai/template-service/src/gate.ts`); attaching a template is what opts into checks, and draft plus formal delivery both export freely without one.

**Project writing charter.** `@paperai/project-service` owns `AGENTS.md` at the project root: a marked, regenerable block carrying the writing workflow, red lines, and a per-document template summary rendered from the repository, plus a created-once `CLAUDE.md` containing `@AGENTS.md` (`src/charter.ts`). Initialization writes it and every durable `paperai` documents change re-renders it through the service's serialized queue, rewriting only on content change and preserving text outside the markers. Codex reads `AGENTS.md`, Claude Code imports it, and the thesis preset's `agent-instructions` row feeds the same file to the built-in agent. An adopted project that already has a `CLAUDE.md` keeps it byte-for-byte and gains one appended `@AGENTS.md` line when it imports the charter in neither spelling, so Claude never silently misses the charter. The two files are one sync: a failure while handling `CLAUDE.md` puts a freshly written `AGENTS.md` back before the error reaches the caller, and the restore handle attempts both files and aggregates their failures.

**Shared gate digest.** `summarizeGate` lives in `@paperai/domain` beside `deliveryBlocked`: severity counts, most severe findings first, one actionable Chinese next step, and a distinct templateless message. The MCP commit and revert results and the native tools embed it as `gateSummary`, so every agent sees violations immediately after each commit without re-running the three-engine-call check; the server-side `deliveryBlocked` interception stays the hard guarantee.

**Native document tools and the thesis preset.** `@paperai/tool-document` registers the ten `paperai_*` tools on `ctx.tools` with the exact MCP names and result fields, delegating to the same domain services; commits stamp `kind: 'agent'`, `client: 'dsh'`, the session id, and the provider/model route of the session's latest durable `request/header` (the creation route only before any request), so a model switched through the picker is what the ledger records, making built-in-agent entries first-class in the version ledger. The roster is two-layered: PaperAI is the one writing agent, and the preset picker chooses its engine. The `dsh` preset directory under `packages/bundle/paperai-web/config/agent-presets/` composes the writing persona, agent-instructions, the document tools, and the complete `standard` row set, so the built-in engine keeps every standard capability; the launcher (`apps/cli/src/profile-boot.ts`) now offers only the product-owned root, so the shared DSH presets — which carry no document capability — stay out of the PaperAI roster, and `ui-paperai-brand` presents the document mark under the `dsh` key. This supersedes the roster curation in the [product profile note](../architecture/2026-08-28-paperai-product-profile.md), which selected the shared `standard` preset by id.

**One access scope for every Agent route.** `@paperai/domain` owns `PaperAccessScope`, `assertProjectInScope`, and `assertMutationAllowed`; `@paperai/project-service` resolves the project that owns a session's workspace root (`resolveForPath`). The native tools resolve the scope from `ctx.sandboxPolicy` per call, and the MCP descriptor lease carries the session workspace root plus a live sandbox-mode reader, so both routes refuse any other project's project, document, or template records (`PROJECT_OUT_OF_SCOPE`, `NO_PROJECT_FOR_SESSION`) and refuse commits, reverts, and exports under `read-only` (`READ_ONLY_SESSION`); the MCP export destination is confined to the session workspace under `workspace-write` (`WRITE_OUTSIDE_WORKSPACE` on the resolved path, then `DESTINATION_OUTSIDE_WORKSPACE` from the export service, which re-checks the real parent directory at publish time so a directory link cannot carry the file out), and full access widens the filesystem, never the document scope. `paperai_list_projects` therefore lists the session's own project only.

**Template-first start flow.** The Workspace sidebar contribution now opens with the built-in template packs instead of a bare "Import Word" bar: each pack member the Host lists is a start row, a form-template member (HIT proposal, midterm report) creates the document from the template in one gesture, a formatting-reference member (thesis writing sample) takes the user's Word manuscript and formats it, and a trailing "no template" row keeps the free-mode import. `@paperai/workbench-service` gains `createFromTemplate`, which installs the member, confirms its contract (built-in members ship reviewed requirements, so the start is not gated behind a separate review), imports the template asset or the upload through the same import-plus-root-commit operation, and binds the contract in that root commit; the member's usage decides the content source, so a form template rejects an upload and a formatting reference requires one. In that shared operation the root commit is the commit point: once it lands the result reports the created document and commit even if the preview fails or the caller cancelled meanwhile (the projection runs without the caller's signal and a failed preview becomes an empty preview with the cause logged), so a retry can never create a duplicate. The flow stays open while the project has no document and folds behind its heading afterwards. `ui-primitives`' `Tooltip` no longer raises its bubble for script-driven focus the platform does not mark `:focus-visible`, which removes the stray "Back to list" bubble that appeared over the auto-focused Workspace back control after a row click.

**Workbench and identity surface.** The workbench splits Templates, Gate, and Export into their own tabs, adds a persistent status bar (attached template or free mode, gate verdict with failing count, version count, all tab-jumping) and renders version provenance as per-author ledger badges. Gate failures offer "Ask the Agent to fix", which drafts the findings into the session composer through a new additive `setDraft` owner operation on ui-conversation's details views. `ui-paperai-brand` installs one `ctx.theme.overrideTokens` layer replacing the DeepSeek blue accent family with the academic pine green in both schemes, `ui-theme` gains the previously consumed-but-undeclared `--dsw-alias-label-quaternary` token, the workbench widens to a 760/1280 details geometry, and ui-layout gains an additive `setDetailsFocus` demand (store flag, solver parameter, `ctx.layout` method) that the workbench exposes as a focus-writing toggle.

## Alternatives considered

**A forced repair loop (post-execute block or turn steering) on gate errors.** Rejected as product policy: the chosen strength is tool-level self-checking plus the existing server-side delivery interception, so an agent that ignores the digest wastes process, not delivery quality.

**Bridging the built-in agent to the existing MCP server.** Rejected: it requires relaxing the `validateActor` whitelist and inventing a token path for non-ACP callers, weakening the lease-bound provenance model, while native tools reach the same services with less machinery and full loop observability.

**Charter via system prompt only.** Rejected: ACP carries no system-prompt channel, so external CLIs would never see the workflow; the project instruction file is the one channel all three routes already read.

**A built-in generic check set for templateless documents.** Rejected for now: the user chose full free mode; a baseline check pack can layer on later without changing the free-mode contract.

**Keeping the `template_missing` finding as a warning.** Rejected: a permanent warning on every templateless commit trains agents to ignore the digest; absence of a template is a mode, not a defect.

**Requiring the review step before a built-in template can start a document.** Rejected for built-in packs: the pack ships reviewed requirements, the user's choice of member is the explicit act of adopting them, and forcing a Templates-tab confirmation before the first document exists made the sidebar unusable as a start surface. Uploaded custom templates keep the draft-then-confirm flow.

**Keeping the shared `standard` preset in the roster and adding document tools beside it.** Rejected: a preset is one whole composition, tools cannot be appended to a foreign preset from outside, and the shared preset must stay free of product services because the `web` and `headless` profiles mount it without them. Re-listing the standard rows inside the product-owned `dsh` preset accepts a manual drift duty in exchange for a roster where every choice can write the thesis.

## Testing

Domain digest, templateless gate, charter rendering/merging/event sync, MCP `gateSummary` embedding, and all ten native tools are covered by package tests (`domain`, `template-service`, `project-service`, `mcp`, `tool-document`); the preset joins the roster in `apps/cli/tests/profile-preset-roots.spec.ts`, and `apps/web/tests/paperai-dsh-preset.e2e.ts` mounts it on the real assembled composition (base, web, and PaperAI overlay) to prove the persona, the ten document tools, and the standard tool set compose together while the host's global tool layer stays empty; the brand key renders in `ui-paperai-brand` tests; the catalog gate proves the tool package is documented. `createFromTemplate` (form-template asset import, reference upload, role and missing-source rejections, root-commit binding) is covered in `workbench-service` tests; the sidebar start flow, its folding, catalog failure retry, and both start gestures are covered in `ui-paperai-workbench` component, controller, and plugin tests; the focus-visible tooltip rule in `ui-primitives` tests.

## Consequences

The two channel classes stay asymmetric: the built-in agent can gain active loop enhancements later, while external CLIs are steered only by the charter file and tool results — acceptable because the hard guarantee is server-side. Document tools are confined to the session's own project on both routes, so an agent that must touch another project needs a session opened in that workspace. The `dsh` preset re-lists the `standard` rows and must track upstream corrections to those rows by hand. The upstream patch set grows by three additive seams (details `setDraft`, layout `setDetailsFocus`, the quaternary label token) that later DSH merges must preserve; the focus demand is transient per-browser state. Built-in template contracts are confirmed by the start gesture, so a pack revision changes what a fresh start adopts without a review prompt; the Templates tab still shows the adopted requirements. The conversation hero copy remains the DSH default because locale namespaces have a single owner and no override seam yet.
