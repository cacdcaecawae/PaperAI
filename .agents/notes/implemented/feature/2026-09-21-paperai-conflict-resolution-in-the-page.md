# Agent Note: PaperAI resolves a draft conflict in the page

Status: implemented

English | [中文](2026-09-21-paperai-conflict-resolution-in-the-page.zh.md)

## Problem

Two writers share one document: the person, typing into the paginated page, and an Agent, editing the same `.docx`. When an outside version changes a paragraph the person already has an unsaved draft on, `restoreEdits` marks that edit conflicted and the block freezes. Until now that was the end of the road. The frozen block kept showing the draft so it could be read, the copy said it was "retained for copying", and the only exits were retyping the merge somewhere else or discarding every draft in the document at once. On a thesis paragraph that is several hundred Chinese characters, "retained for copying" means the writer selects it by hand, pastes it into another window, reads the two versions side by side in their head, and types the result back.

Three smaller holes sat behind it. A conflicted paragraph outside `mapping` — the Agent's rewrite added a citation superscript, an equation, or a field — took no keystrokes at all, so the copy promised a merge the browser could not deliver anywhere. `updateDraft` refused to drop a draft whose node was no longer editable, which is precisely what that rewrite produces, so the text was trapped in the store with no gesture left to clear it. And neither of the two failures that *are* conflicts — `NODE_TEXT_CONFLICT` from the commit service, `changed; reload before applying` from the workbench service — was routed by `actionErrorKey`, so both landed on the generic "try again" and 保存 could be pressed forever without ever reaching the reload that produces a resolution.

## Decision

**The conflicted paragraph is the merge field, and the band above it is the reference.** A `div[data-paperai-conflict]` is manufactured into the page immediately before the paragraph, quoting the document's current text with what the document changed since the draft began marked in place. The marks read against the text both sides started from, not against the draft: the writer's own edits are already in the paragraph below, and a two-way diff would present them as the document's. 用我的 calls `resolveConflict`, which rebases the edit's `baseText` and `baseRevision` onto the current document and clears the flag; the block leaves the `conflicts` set, takes `contenteditable="true"`, and the writer carries on with the same caret, IME, undo stack and ribbon that write every other paragraph. No second editor, no textarea, no modal: the feature is one flag and a piece of page furniture. 用文档的 restores the block's original image and reports, so the edit drops itself; it routes through `finish` rather than a store repaint, which puts it in `history` and makes a press that destroys a draft one Ctrl+Z away. That undo brings the draft back in conflict, band and all: the controller keeps a conflicted draft the writer set aside against the document and revision of the page that took it, and hands it back when that page's undo of 用文档的 reports the same text, including after a switch to another document and back, since a retained preview keeps its undo stack. The page marks that report as the undo, because text alone cannot tell it from a formatting edit that leaves the same words, which stays a new draft. Returned as a fresh draft, it would rebase onto the Agent's text unasked, and 保存 would commit it over the Agent's paragraph without the writer ever choosing 用我的.

**A band never becomes thesis.** It carries no `data-path`, so `mapBlocks` cannot identify it, `report` cannot read a draft out of it and `find` never lands in it; it carries no `data-paperai-change`, so the change navigator skips it; it is `contenteditable="false"`, which `beforeInput` backs up by refusing any input whose range is not wholly inside a mapped block; and `sanitize` strips every `data-paperai-*` but `-change` from anything the Host sends back, so a band can only ever come from the browser. Its quotation is a `p` so that it inherits the document's own face and leading — that is what lets the two texts be read straight down against each other — which means `blocksOf` would return it; nothing runs `blocksOf` over a seated band today because the only caller rebuilds the container first, and the builder's own documentation carries that as a warning.

**Marking stops where it stops working.** `wordDiff` gains a cap parameter: `TOKEN` counts each Han character as one token, so two 600-字 paragraphs are 360,000 cells and the shipped 250,000 bail would render the most ordinary Chinese conflict as one solid deletion and one solid insertion. A band passes 1,000,000, which it can afford because it runs once, for one paragraph, on demand, where a version comparison runs for every changed paragraph. Below a 35% recognised share the band drops inline marking entirely and prints the document's sentence plain, because a genuine rewrite scatters one-character `same` islands through the result and the marks stipple exactly where they are needed most; the head then reads 文档把这段整个重写了 and identification rests where it already rested — the ground, the rule, the sans label and the buttons. Marking also stops when the document still has the very words the draft started from: the conflict is then its formatting, which no word diff can show, and marking the writer's own edits against those words would present them as the document's. The band quotes the document in its own rendered runs, so the reformat itself is on the band, and reads 文档只改了这段的格式，文字和你动笔时一样. A conflict flag outlives the revision that raised it, so when the words and the formatting both read as the draft found them, the document has taken its change back, and the band says 文档改过这段，现在文字又和你动笔时一样 instead.

**A paragraph the browser cannot edit gets an honest band instead of a false promise.** Every identified block now names its node in `data-paperai-node`, mapped or not, which is what gives an unmergeable conflict a seat. Its band quotes the draft verbatim with 复制草稿 and a two-press 放弃这段草稿, and carries no 用我的, because no keystroke can land there. A deleted or unmatched paragraph has no block to host the band, so its band opens the first page, above its first paragraph, on the sheet; discarding it leaves every other draft intact. A band never enters a table, so a cell's band stands before the whole table and names the row and column it speaks for. Because a band can sit far from the caret, the pending bar counts the conflicts, and pressing the count brings the next band into view with focus on its first button. `updateDraft` now always permits dropping a draft; writing one still needs a block that takes writes. A draft whose paragraph turns into one the browser cannot write without its words changing, because an outside edit only added a superscript, a field or a link, is marked conflicted by the preview and gets this band: text-only judgement would leave it clean, on neither the page nor a path to a save.

**What is read against the draft scales with the paper; what is a control does not.** The band lives inside `.paperai-doc`, which carries `zoom`. Its quotation inherits that, because a crisp reference over a shrunken draft asks the eye to compare across two scales. Its 13 px label and 28 px buttons divide by `--paperai-page-relief`, written as `1 / factor` beside the zoom in the same `fit()`, so they hold their screen size at every zoom — a 28 px button at a 50 % fit is otherwise 14 px of target. The reciprocal is applied through `calc()` on each declaration rather than as a nested `zoom`, which would put a second coordinate context inside the editing host that three `getBoundingClientRect` callers read.

**Marks drawn on the sheet take the page's own ink.** Two tokens, `--paperai-page-accent` and `--paperai-page-loss`, hold one value in both schemes, because the paper is white in both and the app's gold resolves to champagne `#e2b457` in dark — 1.9:1 on white. The same audit corrects two defects already shipping on this page: the pending `✎`, the current-change outline and the caret painted that gold alias onto paper, and the comparison's `ins`/`del` tints resolved to `green-900` in dark (a near-black block on a white sheet) and to an undefined token that was silently dropped. Both marks now carry shape as well as colour — demoted-and-struck against forward-and-underlined — and the band's legend names them in words.

Rendered character-format changes also require a choice. The preview compares the draft's original effective runs with the new revision's rendering and records a conflict through `updateDraft`, so direct saves cannot bypass the decision. It preserves every draft run and split paragraph. Copying the first current run's format onto the whole draft would erase mixed formatting and cannot represent either writer's choice. Keeping the draft accepts the current revision and records its formatting relative to that version, so subsequent keystrokes do not revive the same conflict. Only six character properties are compared: bold, italic, underline, size, colour and font. An outside highlight, strike-through or hidden run raises no conflict, the repaint hides it, and the writer's new words take it on at save; the code marks this as a TODO.

## Alternatives considered

**A side panel holding both versions and a merge box.** It is the familiar shape, and it was the one angle that survived the design pass intact. It also builds a second editor: the merge box needs its own IME handling, its own undo, its own formatting, and it separates the text from the page it belongs to, which is the thing this product is for. The band reuses every piece of editing machinery that already exists and adds none.

**A modal conflict resolver, one paragraph at a time.** It orders the work and can show three panes comfortably. It also stops the writing, and a document that comes back from a long Agent turn with four conflicts becomes four modals before a word can be typed.

**Mark the conflict in the gutter only and leave the two texts to the versions panel.** The lightest possible change, and the one that keeps the page quietest. It also leaves the actual comparison two clicks away in a different surface, which is the situation this note exists to end.

**Animate the band's exit as well as its arrival.** The arrival is animated because the band appears unbidden and pushes the thesis down. Every exit follows a press on that band's own button, so it is direct feedback rather than a block vanishing above a live caret, and removing it outright costs no `transitionend` bookkeeping and no fallback timer.

## Testing

`preview-html.client.spec.ts` covers the cap on Han-tokenised input, both band forms, the three absences that keep a band out of the thesis, the rewrite fallback and an emptied side. `editor.client.spec.tsx` drives the four presses against a real shadow root: that 用我的 thaws the paragraph and the next keystroke reports a draft, that 用文档的 is one undo from the writer's text, that 放弃这段草稿 asks twice and disarms on a click elsewhere, and that 复制草稿 selects the quotation so a refused clipboard still leaves Ctrl+C working. `controller.client.spec.ts` covers the rebase, its three refusals, dropping a draft whose block has become uneditable or left the document, a set-aside draft returning in conflict until its page is rebuilt or every draft is discarded, and Ctrl+S reporting why nothing was saved when only conflicts remain. The pending bar's count walking to a band and a cell's band naming its cell are covered in `editor.client.spec.tsx`. `components.client.spec.tsx` covers the conflict failures, verbatim as the gateway delivers them, routed to 刷新 with the bands promised after a save and not after any other action; seating both forms, a draft whose paragraph became unwritable, the caret after a choice, and a compared page carrying no conflict are driven in `editor.client.spec.tsx`. Editor/controller integration tests cover format-only conflicts on mixed runs and split paragraphs, refusal to save before a choice, both choices, and copying or individually discarding a deleted paragraph's draft.

## Consequences

The frozen-block copy is retired: `editor.conflict` and `block.conflicted` no longer say a draft is "kept for copying", because copying is no longer what the writer does with it. The [writing-workflow decision](2026-09-12-paperai-writing-workflow.md) owns draft conflicts, and its conflict sentence is corrected here in the same change: it still described a newer revision conflicting a draft whose text had not moved, which `restoreEdits` stopped doing when the editing-safety round made text alone decide there. A change to the draft's own paragraph that text cannot see, its rendered formatting or content the browser cannot write, conflicts it through the preview instead, as described above. Across a newer revision, a draft whose starting words recur in another node of the same kind also conflicts in `restoreEdits`: the Host carries a node id to the nearest paragraph with the same text, so an insertion above two empty paragraphs swaps their ids, and that band asks the writer to confirm the place.

`resolveConflict` is a client-side store operation with no Remote method behind it. The commit service's own `baseText` check is what the rebase exists to satisfy, and it stays the authority: a rebased draft that loses a second race conflicts again, and the band comes back. That refusal reaches the browser as `internal: <message>`, because the gateway forwards a Host failure's message and not its code, so `actionErrorKey` matches the commit service's messages (`text changed since the`, `head changed:`) beside the workbench's own `changed; reload before applying`; changing those messages in `commit-service` means changing that matcher. An export, check, restore or template change can be overtaken the same way, but it runs only with no drafts, so its guidance asks for a refresh and promises no bands.

The band is browser furniture that is manufactured into a projection, never into the `.docx`, and it is hidden in print. It sets nothing on `.page`: office-cli sizes a page with `min-height`, so a page carrying a band grows with it, and the page's own `overflow-x: auto` keeps a wide table inside the sheet.
