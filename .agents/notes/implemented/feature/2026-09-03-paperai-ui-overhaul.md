# Agent Note: PaperAI start page, tracked-document sidebar, and in-place block editing

Status: implemented

English | [中文](2026-09-03-paperai-ui-overhaul.zh.md)

Partially superseded: layout and draft refresh are governed by the [document-centered workbench decision](../architecture/2026-09-05-paperai-agentero-adoption.md). Other decisions below remain active.

## Problem

The PaperAI client had grown a hierarchy the user could not read. Under each Workspace the sidebar listed template rows, per-template start actions, a New Document row, and folder groups for images, experiments, and code beside the tracked documents and the Session list, so a project's second level mixed configuration, actions, and content. The document view was a set of tabs whose Edit tab presented one semantic node per page, unlike the preview beside it, and its Templates tab asked the user to pick a template per document from a flat catalog. The shell was painted in a pine-green accent over DSH's theme, carried a "论文工作台" descriptor under the wordmark, and opened blank sessions with DSH's "探索未至之境 / 预览版" copy, so the product looked torn from the harness it runs on. The user asked for a rebuild: a sidebar as plain as DSH's, DSH colors and row metrics, one place to configure templates, and an editing view that looks like the document.

## Decision

The product vocabulary is fixed in the root glossary [CONTEXT.md](../../../../CONTEXT.md): 项目, 文档, 会话, 块, 版本, 文档类型, 模板, 格式, 模板库. The template model behind the surfaces is the [template-set decision](../architecture/2026-09-03-paperai-template-model.md); this note records the surfaces built on it.

**Sidebar.** `ui-paperai-workbench` contributes one `sidebar.workspaces.content` entry: a "文档" section listing the project's tracked Word documents with their document type and no actions, while DSH's `ui-workspace` keeps the Session section, the New Session action, and its collapse behavior in the same [Workspace detail](2026-08-30-workspace-detail-navigation.md). `ui-paperai-brand` overlays the `workspace` and `conversation` locale namespaces so the shell says 项目 where DSH says 工作区 (list heading, back action, detail and Session region labels, picker, rename and delete dialogs). The overlay rides the `LocaleRuntime.override(ns, dicts)` seam of `@deepseek-ai/dsh-client-locale`, which keeps one overlay per namespace and locale, consults it before the owner's dictionary, throws on a second overlay for the same pair, and returns a disposer.

**Start page.** `ui-conversation` declares a `conversation.hero.content` single root-scope slot whose owner share carries the blank session id, its Workspace id, and an `openWorkspacePicker` callback, with the DSH headline (mark, title, preview badge) as fallback. PaperAI's `StartPage` occupies it. With a project it shows the mark and the project name, the line "本项目模板：X · 更换…", one action per format in the project's template set (a form template starts "新建{类型}" directly; a formatting reference offers "导入初稿，套{类型}格式" and takes the manuscript file), and "导入 Word，自由写"; a project that never decided its template gets the template dialog once per visit, and closing it is the answer for that visit. Without a project it shows the mark, "PaperAI", and "新建或打开项目", which opens DSH's Workspace picker. Choosing a previously registered directory reopens its existing project, documents, and template decision; the start page explains this behavior. The DSH composer with its Workspace and agent-preset chips stays below.

**Templates page and dialog.** A `settings.section` entry "模板" and the project dialog render one `TemplateLibraryView` over one shared library store: built-in and custom sets with their formats, "添加自定义模板", per-type "添加格式" with the Word file and its usage (填写用的表单模板 or 排版参考的范例), replace or remove a format, and delete a custom set after confirmation; in project context the same view adds "用于本项目" and "不用模板，自由写".

**Document view.** The `conversation.details.view` entry `paperai` renders the Host preview inside an open shadow root after sanitizing it: `script`, `iframe`, `object`, `embed`, `link`, `meta`, `base`, form controls, and `noscript` are dropped, `on*` attributes and `javascript:` or `data:` URLs are stripped, and the document's own `style` elements move into the shadow tree so its typography stays inside. Every paragraph, heading, list item, and table cell is paired with an editable semantic node by normalized text and position; clicking a block replaces it in place with a textarea, 保存 commits one `replace-text` mutation as one version through the existing commit path, Escape cancels, and an unmatched block says it can only be changed by the Agent. The toolbar carries the chips 模板, 门禁 (with the failing count), and 版本 (with the count), an 导出 menu (草稿 or 正式版), and the focus toggle over `ctx.layout.setDetailsFocus`; the three chips open one side panel at a time instead of tabs. The template panel shows the bound format and its requirements, asks the document type with the Host's guess (`suggestDocumentType`: title first, then opening paragraphs) for confirmation, applies the project format by type, detaches it, and opens the project template dialog. It disables applying only when the bound pack member and source version already match the selected project format, so switching sets or replacing one format keeps the document's current type applicable. The gate panel lists findings with their location, runs 检查, and "让 Agent 修复" drafts the findings into the composer through ui-conversation's `setDraft`. The versions panel is a timeline with author badges and a current marker; one version at a time unfolds its paragraph-level changes through `diffVersion`, and a restorable version offers 恢复到此版本. A `paperai/document-changed` event for the open document reloads it at once when no draft differs from its base text; otherwise a banner offers 刷新, which keeps the draft when the edited block still reads as it did and drops it with a notice otherwise. The layout profile is centerMin 560, detailsMin 420, detailsDefault 760.

**Brand.** `ui-paperai-brand` installs no theme token layer: every interactive color is DSH's, and PaperAI rows follow DSH row heights, radii, and type sizes. The mark is path data traced from the supplied logo (robot head, pen nib, and an open book narrowed to a golden rectangle), checked in as `brand-paths.ts` and rendered as inline SVG in `currentColor`; the wordmark is "PaperAI" outlines at the DSH wordmark's height. The descriptor and the DSH hero copy are gone.

**Host.** `@paperai/workbench-service` exposes `overview` (project name, template decision, document rows), `setProjectTemplate`, `listTemplateLibrary`, `createTemplateSet`, `deleteTemplateSet`, `addTemplateFormat`, `removeTemplateFormat`, `importDocument` (a free-writing document of type `other`, no type asked), `createFromTemplate` (resolves the format from the project's set and the document type; a form template becomes the document, a formatting reference governs the upload), `applyTemplate` (one commit carrying `set-document-type` when the type changes and `bind-template`), `detachTemplate` (`unbind-template`), `suggestDocumentType`, `diffVersion` (both immutable snapshots read through the document engine), `exportDocument`, `open`, `readNode`, `commit`, `validate`, and `restore`. `@paperai/template-service` gains `TemplateLibrary`, which persists custom sets at `<storageRoot>/library/library.json` through an atomic temporary-file write with their Word files in the content-addressed asset store, and `listPacks` reports built-in and custom kinds. `@paperai/project-service` records the choice with `setTemplateChoice`, writing `templatePackId` and `templateDecidedAt` on `ProjectRecord` (`null` records the choice to write freely). `@paperai/domain` adds the `unbind-template` and `set-document-type` mutations; `@paperai/commit-service` validates a binding against the document type the same commit sets; the MCP server and the native `paperai_commit_document` tool accept both mutation kinds, so an Agent rebinds a document by type.

Document-change notifications refresh loaded project lists, including documents created by an Agent in another session. Unsaved block text survives selecting the same block, document navigation attempts, and reconnects. Opening or starting another document requires saving or cancelling the draft first. A reconnect reads the current head without replacing the draft; a missed version is offered through the external-update banner, and a newer notification received during the read remains pending. The project overview carries the chosen `templatePackId` separately from the available set, so deleting a set displays a missing-template state instead of changing the project's decision to free writing. A failed initial project read can be retried from the start page.

The block editor's explicit external-refresh policy supersedes the browser conflict controls in the [transient-state note](../bug-fix/2026-08-29-paperai-transient-state-lifetimes.md); that note continues to own Host gate-report ordering.

## Alternatives considered

**Keep template rows and start actions in the sidebar.** A project's second level then holds configuration and actions beside content, which is the hierarchy the user could not read; the start page has the room and the context (the blank session's Workspace) that a sidebar row lacks.

**Tabs with a node-per-page editor.** The Edit tab showed one paragraph per page and nothing of the document around it; block editing in the preview keeps the document as the only view and turns every click into the same `replace-text` commit.

**A rich editor over the preview HTML.** The HTML is generated presentation; the Working DOCX is authoritative, and an editable DOM would need a second document model and a round trip back to Word. A textarea per block keeps every change a semantic mutation on a known node.

**A PaperAI accent color layer.** The pine-green override was what made the product look torn from DSH; the user asked for DSH colors, so the brand contributes only the mark and the wordmark.

**Forking the `ui-workspace` and `ui-conversation` dictionaries for "项目".** A fork duplicates every key for a handful of words; the locale overlay seam changes only the keys a product renames and keeps the owner's dictionary intact.

**A full-page history viewer.** The user asked for VS Code's Git experience: a timeline where one version unfolds its diff and can be restored, which one panel provides.

## Testing

Package tests cover the Host methods and rules (`workbench-service`, `template-service` library, `project-service`, `commit-service`, `mcp`, `tool-document`), the locale overlay (`locale`), the hero slot and its fallback (`ui-conversation`), the brand occupants (`ui-paperai-brand`), and the workbench controller, the four components with a jsdom shadow tree, the plugin registrations, and the DSH-token styling rules (`ui-paperai-workbench`). The assembled-browser suites `apps/web/tests/paperai-workspace-navigation.e2e.ts` and `apps/web/tests/paperai-permissions.e2e.ts` pin the sidebar detail, the start page, and the document view on the real PaperAI composition.

## Consequences

The upstream patch set grows by two additive seams, the `conversation.hero.content` slot and `LocaleRuntime.override`, beside the earlier `setDraft` and `setDetailsFocus`; later DSH merges must preserve all four. The Host preview is treated as untrusted markup at the client, so a preview that relies on scripts or external resources renders without them. Block editing reaches only blocks whose text matches an editable node; table cells, figures, and captions the Host does not expose as editable nodes are the Agent's. Deleting a custom set leaves the projects that chose it showing a missing template until they choose again, while installed formats keep working. This note supersedes the sidebar start flow, the tabbed workbench with its status bar, and the theme layer described in the [multi-agent thesis writing baseline](2026-09-02-multi-agent-thesis-writing-baseline.md); that note's other decisions (free mode, charter, gate digest, native tools, access scope) stand, and its consequence that the hero copy had no override seam no longer holds.
