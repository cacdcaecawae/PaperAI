# Agent Note: PaperAI 极简工作台、常驻文档引擎与外部修改

Status: implemented

[English](2026-09-09-paperai-minimal-workbench-and-outside-edits.md) | 中文

部分取代：[写作流程决策](2026-09-12-paperai-writing-workflow.zh.md)拥有编辑命令、草稿冲突、默认写作模式及面板行为。下述常驻引擎生命周期、版本发布、外部文件捕获与主题归属继续有效。

## 问题

在 23 KB 的文档上提交一段要 13 到 15 秒：每条 OfficeCLI 命令都新起进程，每次提交都等 Host 重新渲染预览。浏览器像零件拼出来的而不像设计过的：起始页重复 DSH 标题，ACP 设置页带横幅和统计数字，文档视图挂着胶囊标签，版本面板盖在它描述的页面上。工作文件在 PaperAI 之外被改过（Word、文件同步、早期导入缺陷）时写作者会卡住：提交服务拒绝编辑，要求"先把外部修改记为一个版本"，而产品里没有这个操作。编辑本身也不像 Word：点一下段落就换成带按钮的文本框，一次只能改一段；输入框旁的 Agent 状态标签弹出的浮层还会被对话栏裁掉。

## 决策

OfficeCLI 引擎为每个文件保留一个常驻进程跨操作复用，空闲 `residentIdleMs`（默认 2 s）后关闭。常驻期间其他程序可以读取并就地写入该文件，但不能重命名、替换或删除，因此窗口很短，且 PaperAI 中每条会替换或删除引擎碰过的文件的路径都先调用 `release()`：commit-service 的候选文件与工作文件、document-service 的暂存导入副本。没有常驻进程时 `release()` 为空操作。

段落提交不再等待 Host 预览。Host 返回已提交的文档和空预览（`projectOpen(..., 'skip')`）；浏览器把已提交文字写进当前显示的预览，并在后台重新打开文档拉取渲染结果。临时补丁按段落编辑器的映射方式定位块：带地址（`data-path`）、同类（正文段落或表格单元格）、同文字，并取该节点在同文字同类节点中的序号。映射说不出位置的块保持原样直到渲染到达。后台渲染只在属于同一修订时替换预览；带有更新头的渲染触发既有的外部更新提示，而不进入当前投影。

`paperCommits.captureExternal` 把与当前版本不一致的工作文件原样记为一个新版本：字节不变，新增快照与提交记录，无操作，消息为"载入外部修改"。工作文件已与当前版本一致时拒绝。工作台以 `captureExternal` Remote 暴露它并重新读取体检报告。被拒绝的提交显示原因并提供"记为新版本"，记录后重新打开文档，块文字未变时保留草稿；项目体检对每份标为外部修改的文档提供同样的操作。

版本对比只在恰好一个带地址的正文块仍承载改动或新增文字时就地标记；删除的段落，以及文字已消失或重复的改动，列在面板里而不猜位置。文档面板（模板、门禁、版本）作为页面旁的一栏打开，通过布局的详情聚焦占据内容区，页面保持宽度、对话栏让位直到面板关闭；列宽不足以并排时面板覆盖在页面上。页面按列宽缩放；详情栏默认 860 px，可完整显示一页 A4。

段落直接在原位书写。每个已映射的块是 `contenteditable`（Host 不得预先把任何块声明为可编辑，净化时会剥掉该属性），`input` 事件把该块报给控制器，工作台保存的是一组草稿而不是一条：`updateDraft(nodeId, draft)` 新增或替换某块的草稿，`null` 则去掉它；`cancelEdit` 全部放弃；`commitEdit` 把所有草稿作为一次提交发出，每块一条 `replace-text` 变更；临时预览补丁先按原文定位所有块，再统一改写。改过的块像对比标记一样带金色标记与底色；所在块在 PaperAI 之外被改过的，标记转红，放弃该草稿前不能保存。回车不会拆段（新增段落交给 Agent），Ctrl/Cmd+回车保存，Esc 让一块回到 Host 的渲染，其中的字符格式来自渲染时留下的克隆。页面底部一条浮条统计改过的段数并提供"放弃修改"与"保存"；保存进行中或正在对比版本时，块不可编辑。

浏览器遵循同一套视觉语法：`ui-paperai-brand` 的墨金 token 层（取代了 [UI 改版笔记](2026-09-03-paperai-ui-overhaul.zh.md)中「不安装 token 层」的那一半）、12 到 13 px 界面文字、细线、8 与 12 的圆角、每屏一个实心动作（文档视图里是"导出"，待保存浮条里是"保存"），Codex 与 Claude 图标保留在人们习惯看的位置。起始页以模板、文档数和最近编辑标识项目，列出已追踪文档及类型徽标，所有格式从一个菜单开始；ACP 设置呈分组卡片。输入框旁的 Agent 状态标签及其浮层已去掉：检测放在 Agent 设置页，工作台不再填充 `conversation.hero.agentPreset.status`，也不再依赖 `ui-agent-preset`。

## 考虑过的替代方案

**直接在工作文件的常驻进程上修改并 `save`。** 省掉候选副本和每次提交的一次冷启动，但保存中途崩溃会损坏写作者的文件；保留候选并替换的发布方式。

**保留覆盖式面板并按需加宽列。** 布局未暴露宽度设置器，详情宽度是用户的偏好。详情聚焦是现成的杠杆，也符合 mockup 中历史替换 Agent 栏的设计。

**为删除段落和重复文字猜测位置。** Host diff 不携带位置；标在错块上的记号读起来像错误的编辑。列出胜过猜测。

**在被对比版本自己的预览上显示 diff。** 需要 Host 渲染快照的方法；等历史视图值得时再做。

**保留文本框编辑器、只改样式。** 挂在段落旁的任何座位读起来仍是表单，一次只开一个编辑器也不是人们修改一页的方式。直接在渲染出的块里打字才是 Word 的做法；纯文本编辑在改字时保住块内的字符格式，并把每块一个字符串交给既有的 `replace-text` 变更。

**修好标签浮层的定位。** 换个锚点仍会在设置页之外多出第二个 Agent 状态；去掉后这一行更安静。

## 测试

单元覆盖：document-engine-officecli 的常驻复用、空闲关闭与空操作释放；document-service 与 commit-service 的暂存释放与记录外部修改；workbench-service 的 Remote 与体检路径；ui-paperai-workbench 的补丁序号、唯一匹配标记、带修订校验的延迟刷新、来自提示与体检的记录操作、面板栏，以及原位改写（可编辑块、输入上报、多块提交、Esc 复原、待保存浮条）。PaperAI 浏览器 golden 跟随起始页、Agent 设置标签、860 px 列宽、相对日期，以及取代段落编辑器的待保存浮条；浏览器流程像写作者一样以全选加插入文字改写段落。

## 后果

Word 与 PaperAI 可以交替编辑同一文件：PaperAI 拒绝在未记录的外部字节上继续，但一次点击即可记为版本并继续编辑。PaperAI 操作后约两秒内其他程序不能重命名、替换或删除该文件。参考文档上的提交约 5 秒可见，而非 13 到 15 秒，渲染预览约一秒后到达；被重写块内的字符格式在此之前会暂时抹平。含重复文字的文档在页面上显示的对比标记更少，这些改动改为列在面板中。一次保存前可以改多段，它们记为一个版本；页面上不能拆段或加段，被外部改过后又改写的段落必须先放弃，其余才能保存。输入框一行不再显示 Agent 检测，Agent 设置页负责。新增 Remote 方法仍需目录登记（`linkedTypePages`）与生成文档，并手工镜像中文目录中的行号引用。
