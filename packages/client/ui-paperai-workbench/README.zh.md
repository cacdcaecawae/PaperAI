# @paperai/ui-workbench

[English](README.md) | 中文

基于 DSH 插件和 slot 的 PaperAI 浏览器工作台。左侧显示项目和受管理的 Word 文档，中间显示文档，右侧显示 Agent 对话。产品通过 `ctx.layout.configure` 安装 `PAPERAI_LAYOUT_CONFIG`：`detailsPosition: start`、`centerMin: 360`、`detailsMin: 480`、`detailsDefault: 860`、`detailsMax: 1280`，允许当前空白 Session 显示文档，两栏无法并排时聚焦文档。打开 Word 后空白对话采用紧凑布局；引用选区会显示对话，空间足够时文档仍在旁边。

本插件贡献文档列表和项目体检、项目起始页、模板设置页和 `paperai` 文档视图。Workspace 导航、对话、权限控制和模型选择仍由 DSH 提供。注册通过 `slots.inject()` 跟随 slot 声明者的生命周期。颜色和共享控件来自 DSH。

起始页创建或打开项目目录，以模板、文档数和最近编辑时间标识项目，列出已追踪文档及其类型，并通过一个菜单从项目模板格式新建或自由导入 Word。项目模板对话框与设置页共用模板库存储。尚未回答的模板选择会在每次访问时弹出一次对话框。[Host 服务](../../paperai/workbench-service/README.zh.md)拥有导入限制、模板语义和文档操作。

文档视图在 shadow root 中渲染经过净化的派生 HTML，保留嵌入式位图。只有带有提供方 `data-path` 的块才按文本、单元格归属和阅读顺序参与匹配。没有地址的页眉、页脚保持只读，不会消耗同名正文的匹配项；未匹配或只读的单元格不能指向正文段落。已映射的段落、标题、列表项或单元格直接在原位书写。选中的文字可加粗、倾斜、加下划线和改字号，该块随后以 Word 存储的 run 形式传输，每个 run 只声明它相对本块的覆盖；没有覆盖的块仍按纯文本提交。一次保存前可以改多个块，通过 `commit` 记为一个版本。Ctrl/Cmd+Enter 保存，Esc 让一个块回到文档原样，回车不会拆段。模板、门禁结果和版本分别在页面旁的独立面板栏打开，面板占用对话栏的位置直到关闭，按需加载次级内容。点选一版即在文档上对比：改动的词就地标出，删除的段落以删除线重现，底部浮层在各处变化间跳转，对比期间段落保持只读。导出显示生成路径，正式导出未通过门禁时打开检查结果。若因工作文件在 PaperAI 之外被修改而拒绝提交，会提示把该文件记为一个新版本并重新打开文档、保留草稿；项目体检对它标出的每份文档提供同样的操作。

`Config.retainedPreviews` 为正整数，默认 `2`，包含当前预览。最近预览保留 DOM、滚动位置和段落草稿。淘汰预览时释放较重的渲染内容，轻量草稿与滚动偏移保留至插件卸载。文档变更使后台预览失效，重新连接会读取已加载的投影。其他会话修改同一段时保留草稿供复制或取消，禁止将其直接保存到新段落。已有未保存草稿时不能新建文档；若在导入或从模板创建期间开始写草稿或切换文档，当前视图会保留，完成后的文档加入项目列表。

选择 Word 中已映射的文字会显示“交给 Agent”。点击后插入可移除输入引用，包含文档 id、路径、revision、当前提交、块 id 和精确文字。序列化内容在异步发送前冻结，切换文档不会改变引用对象。既有引用 codec 处理剪贴板持久化、移除和消息序列化。仅选择文字不会发送消息。

项目体检首先执行只读扫描；用户恢复前，方案预览明确显示缺失的工作文件和准确版本。[提交服务恢复流程](../../paperai/commit-service/README.zh.md)负责校验和发布。

插件先挂载生成的 `@paperai/workbench-service/remote` descriptor，再注册 UI。传输类型来自 `@paperai/workbench-service/types`。不依赖 React 的控制器拥有浏览器状态、拒绝过期回执，并在卸载时释放订阅和未完成的读取。

打开、导入或创建文档时，沿用当前项目中已选中的 Session，包括已经开始 Agent 对话的会话。连接其他项目时才在目标项目中解析 Session。再次打开当前文档会保留草稿。

已发送的 Word 引用显示选中文字，来源信息可按需展开。序列化消息以文档标题开头；复制结果和会话日志保留完整来源。项目体检显示本地化问题名称，路径分隔符统一为正斜线。

## 模型体验

### 显式 Word 上下文

#### 模型看到的内容

只有用户保留并提交的引用才进入普通 `user/message` 内容。每条引用包含精确文字及文档、版本来源，因此 DSH 日志无需读取当前预览就能重建上下文。

#### Token 影响

提交选区会将文字和来源加入该消息；预览和诊断不增加 token。

#### KV Cache 影响

正常追加用户消息；诊断和导航不改变请求前缀。

## 已知限制与后续工作

- DOCX 始终是权威正文；浏览器 HTML 和草稿不是第二份文档存储。
- 编辑限于已映射块的纯文本。未映射内容和富文本格式需要 Agent 与文档引擎处理。
- 预览缓存和草稿属于浏览器生命周期状态，刷新页面后不恢复。
- 缓存模型描述此前初始化的情况，只有已连接适配器才能决定当前选择。
