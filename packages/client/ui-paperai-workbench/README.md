# @paperai/ui-workbench

English | [中文](README.zh.md)

DSH-native PaperAI document UI plugin. It contributes a project-detail resource view to `sidebar.workspaces.content` and a complete `paperai` view to `conversation.details.view`; it does not replace the Workspace browser, conversation shell, Tool details, or `ui-layout` geometry.

The Workspace contribution leads with a template-first start flow and then renders the fixed Documents, Templates, Images, Experiments, and Code groups from one Host-projected flat list. The start flow lists every built-in template pack member the Host offers (`listTemplates`), headed by its pack name: a form-template member such as the HIT proposal or midterm report creates the document from the template in one gesture (`createFromTemplate`), a formatting-reference member such as the thesis writing sample asks for the user's Word manuscript and formats it, and a trailing "no template" row keeps the free-mode Word import with its role selector. Both template rows bind the member's contract in the root commit, so the new document opens already gated. The flow stays open while the project has no document and folds behind its heading afterwards; the user can reopen it at any time. Each tree row carries an opaque resource id, path, depth, kind, optional working status, and an explicit `openable` capability. Only openable rows render as buttons. Selecting one connects the Workspace to its reusable blank Session, opens that Session, selects the `paperai` details view, and asks the Host for the document projection. Non-openable rows remain ordinary tree rows rather than dead controls.

The authoritative body is always the Working DOCX. The right column reuses the DSH details-host structure: a compact title row, line tabs, weak separators, ordinary 13–14px type, and row-level actions. Preview renders OfficeCLI-derived HTML in a strict read-only sandbox; that complete HTML never enters an edit callback. Edit renders the Host-projected semantic outline and requests a temporary plain-text buffer for only the selected editable node. The buffer is browser-local until **Commit and create version** submits one `replace-text` mutation addressed by `nodeId`. Switching nodes, opening another document, restoring a version, template changes, gate checks, and exports are disabled while an edit or conflict is unresolved. An external reload rebases the draft when that node is unchanged. When the same node changed, the workbench advances to the latest revision, retains both texts, and lets the user adopt the local text, adopt the external text, or edit and accept merged text before committing from the latest node buffer. A later revision that changes another node advances the immutable buffer again without clearing those unresolved conflict inputs or the edited merge draft; only an explicit resolution removes the conflict. The reload consumes only the external notification captured when it starts, so a newer notification received in flight remains actionable. Discard changes resets a non-conflicting buffer locally. Versions show durable summaries plus human or Agent provenance as one ledger badge per row — Human, DSH, Codex, or Claude, with the exact model — and expose Restore only for Host-marked restorable commits. Templates, Gate, and Export are separate tabs: Templates owns the built-in packs, custom upload, review, and association flow; Gate shows the attached template, its latest findings, one backed Run gate action, and an "Ask the Agent to fix" action that drafts the failing findings into the session composer through the details host's `setDraft` owner operation without sending; Export owns draft and formal delivery. A persistent status bar above every tab surfaces the attached template (or the templateless free mode), the gate verdict with its failing count, and the version count as tab-jumping chips, plus a focus toggle that demands the layout's whole-content-area details focus (`ctx.layout.setDetailsFocus`) and releases it on exit or unmount.

`@paperai/workbench-service/types` is the sole owner of the transport data types; this package re-exports those types and keeps only browser store state locally. `PaperAIWorkbenchRemote` is a `Pick` of the generated `TypertClientRemote['paperaiWorkbench']` namespace, not a handwritten RPC interface. The plugin injects `@deepseek-ai/dsh-api-remotes`, imports the `@paperai/workbench-service/remote` descriptor, and awaits `ctx.remote.$mount()` before constructing the controller or registering UI. A descriptor-mount failure rejects plugin activation instead of producing an optional guessed namespace, and disposal unmounts the descriptor with the plugin lifecycle. The generated `list`, `open`, `readNode`, `commit`, `validate`, and `restore` methods use branded ids and `RemoteResult` envelopes. `readNode` returns one plain-text buffer with `nodeId`, `baseRevision`, and `baseCommitId`; `commit` sends node mutations against those base values and must return the created commit id plus fresh document and selected-node projections. It has no whole-document HTML input. Restore also creates a recoverable commit instead of moving the head silently.

`PaperAIWorkbenchController` is React-free and receives the already mounted generated namespace. It owns one stable resource store per Workspace and one workbench store per Session, including the selected-node phase, immutable Host buffer, current draft, external-conflict inputs, dirty flag, and action state. It aborts superseded cancellable reads, rejects stale node responses and buffers from another document revision, folds Remote rejections into display state, preserves the selected tab across document updates, refreshes observed projections after `connection/reset`, and rejects callbacks after plugin disposal. Slot registration follows declaration lifetimes through `slots.inject()`, including declarer unload and reload.

The plugin does not choose a details width. Its root fills the column supplied by `ui-layout`. The edit view splits the semantic outline and selected-node editor at ordinary widths, then stacks them through a container query when the column narrows; version metadata adapts through the same query. The project resource sections follow the Workspace detail's compact row rhythm and shared hover/focus transitions; an empty project leads with the template start rows and the free-mode Word import without inventing placeholder categories. Entering a Workspace detail focuses its Back control, and opening a same-node conflict focuses the comparison heading before the user chooses or edits a resolution. Hidden upload inputs stay outside the accessibility tree, role selectors announce their current value, and Host/provider diagnostics remain in logs while the UI shows localized recovery text. These sections do not render in the Workspace list, flat, search, or Ungrouped paths because those decisions belong to `ui-workspace`.

## Model Experience

### Browser document projection

#### What the model sees

Nothing from `@paperai/ui-workbench`; it renders Host document projections and does not register a prompt, Tool schema, or Session event.

#### Token effect

No tokens are added because the package neither assembles nor sends a model request.

#### KV Cache effect

No cache prefix changes because the package contributes only browser UI and explicit document RPC actions.

## Known Limitations and Deferred Work

- The package consumes the Host-owned protocol and generated descriptor but does not provide the Host implementation or compose itself into a bundle.
- The v1 shared protocol exposes plain-text selected-node buffers only, and the editor has no formatting toolbar. Rich-node editing requires a Host protocol addition rather than a private client DTO.
- The browser never maintains Markdown or complete editable HTML as a second body. Preview HTML is a derived projection; every durable body change is applied to the Working DOCX through `commit`.
- The Host owns preview generation and sanitization. The browser additionally uses a strict iframe sandbox but is not the document sanitizer.
