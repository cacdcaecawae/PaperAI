# @paperai/ui-workbench

English | [中文](README.zh.md)

DSH-native PaperAI UI plugin. It contributes four entries to shipped DSH slots and nothing else: the project's document list to `sidebar.workspaces.content`, the project start page to `conversation.hero.content`, the Templates page to `settings.section`, and the complete `paperai` document view to `conversation.details.view`. It does not replace the Workspace browser, the conversation shell, Tool details, or `ui-layout` geometry, and it speaks the product vocabulary of the repository glossary (`CONTEXT.md`): a project, its documents and sessions, the blocks and versions of a document, the document type that picks a format out of the project's template, and the template library that holds every template. On activation it also installs PaperAI's wide details-column layout profile (`PAPERAI_LAYOUT_CONFIG`: current-Session details, focus mode when the column is narrow), turns off the DSH welcome notice and DeepSeek-credential onboarding, and initializes a PaperAI project for every Workspace as soon as it enters the DSH ledger, so the directory picker really means "create or open a project".

The sidebar contribution is one section, Documents: the project's tracked Word documents as rows in the DSH session-row idiom, each showing the document name and its document type when it has one, the selected row marked current. There are no template rows, no new-document or folder groups, and no buttons beyond a Retry on a failed read; an empty project gets one line pointing at the start page. Selecting a row connects the Workspace to its reusable blank Session, opens that Session, selects the `paperai` details view, and asks the Host for the document projection. Host and provider diagnostics stay in logs while the rows show localized recovery text. The Workspace list, flat, search, and Ungrouped paths remain `ui-workspace` decisions, so the section renders only inside a project's detail.

The start page occupies the blank-session headline. With a project it shows the brand mark and the project name, one line naming the project's template (the chosen set, or that the project writes freely, or that nothing has been chosen yet) with a Change or Choose control, and one outline button per format of that template in thesis order: a form template creates the document of its type in one gesture (`createFromTemplate`), a formatting reference asks for the user's Word manuscript first and formats it, and a trailing "Import Word, write freely" imports a manuscript without asking for a type (`importDocument`). Every start gesture connects the Workspace, shows its Session, opens the document view, and then establishes the document, so the new Working copy lands in the column the user is looking at. The mark rides the `paperai.start.mark` seat this entry declares, so the brand plugin supplies the same mark it gives the sidebar; an empty seat shows no mark. A project that never decided its template is asked once per visit through the template dialog, and closing the dialog counts as the answer for that visit. A file that is not a non-empty `.doc` or `.docx` of at most 32 MB is refused before any upload, and a failed start shows localized copy instead of the Host diagnostic. Without a project the headline shows the mark, the `PaperAI` name, and one call to action, "Create or open a project", which opens the DSH Workspace picker through the owner's `openWorkspacePicker`.

Templates are global configuration, not project content. The Templates settings page and the project's template dialog render the same library view over the same library store: every set with a Built-in or Custom pill, its formats listed by document type with their usage (a form to fill in or a formatting example), and for custom sets the actions to add a format (document type, usage, then the Word file; the type menu starts on the first type the set lacks and the format is named after the file), remove one, or delete the set after an inline confirmation; "Add custom template" creates an empty set by name. Inside a project the view adds "Use for this project" per set (disabled while a set has no format), marks the current choice, and offers "No template, write freely". A library change re-reads every loaded project overview so the start buttons and the document view's template panel follow it.

The document view is the document itself. The `DetailsViewShell` header carries the title and path; under it sits a toolbar of chips: the bound format's name (or "No template"), the gate verdict with its failing count while a format is bound, the version count, an Export menu (draft or formal delivery), and a focus toggle that demands the layout's whole-content-area details focus (`ctx.layout.setDetailsFocus`) and releases it on exit or unmount. The Host's preview HTML renders inside an open shadow tree: active content (`script`, frames, embeds, form controls), inline event handlers, and `javascript:` or `data:` URLs are stripped first, and the document's own stylesheet stays inside the shadow root. Every paragraph, heading, list item, and table cell is paired with an editable semantic node by text and reading position; clicking one replaces it in place with a plain-text editor (Escape cancels, Ctrl/Cmd+Enter or Save commits) whose save sends exactly one `replace-text` mutation addressed by `nodeId` through `commit`, creating a version. A block that matches no editable node reports that the Agent can change it, and an unsaved draft blocks switching documents, starting another document, editing another block, and actions that create or change a version until it is saved or cancelled. Selecting the edited block again preserves its draft. The chips open one panel at a time beside the document. Template shows the bound format, its requirements, and Detach, then applies the project template by document type, seeded with the Host's guess (`suggestDocumentType`) that the user confirms, with a link to change the project template. Gate explains the check, runs it, lists the findings, and drafts the failing ones into the session composer through the details host's `setDraft` without sending. Versions is the timeline as Git history: summary, one ledger badge per author (Human, DSH, Codex, or Claude with the exact model), time, the current marker, "Show changes" loading that version's paragraph diff on demand, and Restore for Host-marked restorable versions, which creates a new version instead of moving the head silently. A durable head committed elsewhere reloads the view at once when nothing is in progress; while a draft is dirty the view shows a banner with Refresh instead, and the refresh keeps the draft when its block still reads as it did and drops it with a notice otherwise. Exports report the written path, and a formal delivery blocked by the gate opens the Gate panel with a localized explanation.

`@paperai/workbench-service/types` is the sole owner of the transport data types; this package re-exports them and keeps only browser store state locally. `PaperAIWorkbenchRemote` is a `Pick` of the generated `TypertClientRemote['paperaiWorkbench']` namespace, not a handwritten RPC interface: `overview`, `setProjectTemplate`, the five library methods, `importDocument`, `createFromTemplate`, `open`, `commit`, `validate`, `restore`, `applyTemplate`, `detachTemplate`, `suggestDocumentType`, `diffVersion`, and `exportDocument`, all with branded ids and `RemoteResult` envelopes. The plugin injects `@deepseek-ai/dsh-api-remotes`, imports the `@paperai/workbench-service/remote` descriptor, and awaits `ctx.remote.$mount()` before constructing the controller or registering UI; a mount failure rejects activation instead of producing a guessed namespace, and disposal unmounts the descriptor. `PaperAIWorkbenchController` is React-free and owns three kinds of stable stores: one project store per Workspace mirrored into one aggregate project directory that the sidebar, start page, and document view select from; one template-library store shared by every surface that shows the library; and one workbench store per Session holding the document, the block edit, the open panel and its diff, the type suggestion, the export receipt, and the pending external head. It aborts superseded reads, rejects projections that belong to another document, Workspace, or Session, folds Remote rejections into display state, keeps the open panel across same-document updates, refreshes every loaded projection after `connection/reset`, consumes `paperai/document-changed`, and rejects callbacks after plugin disposal. Slot registrations follow declaration lifetimes through `slots.inject()`, including declarer unload and reload.

Everything paints in DSH's own vocabulary: `--dsw-alias-*` tokens only, no product accent, no literal colors, no drop shadows, and DSH primitives (`DetailsViewShell`, `Button`, `Menu`, `Modal`, `Pill`, `DisclosureRow`, `StateDot`) instead of a private component set. Sidebar rows keep the session-list metrics (32px rows, 8px radius, 14px type under 34px headings), the start page keeps the DSH hero headline geometry, and the document view fills the column `ui-layout` supplies, moving the open panel to full width through a container query when the column narrows. Hidden upload inputs stay outside the accessibility tree, menus announce their expansion, and every failure the user sees is localized copy while diagnostics stay in logs.

Document-change notifications refresh loaded project lists, including documents created by an Agent in another session. A failed initial project read can be retried without remounting the start page. The project overview retains its chosen `templatePackId` when that set is deleted, so the start page and template panel display a missing-template message and the chooser does not mark free writing as the current decision. Reconnecting keeps unsaved block text and checks for missed document changes; a newly observed head appears in the existing Refresh banner, and a later live notification takes precedence over an earlier reconnect read.

## Model Experience

### Browser document projection

#### What the model sees

Nothing from `@paperai/ui-workbench`; it renders Host document projections and does not register a prompt, Tool schema, or Session event.

#### Token effect

No tokens are added because the package neither assembles nor sends a model request.

#### KV Cache effect

No cache prefix changes because the package contributes only browser UI and explicit document RPC actions.

## Known Limitations and Deferred Work

- The package consumes the Host-owned protocol and generated descriptor but does not provide the Host implementation or compose itself into a bundle.
- Editing is plain text per block: a block is one paragraph, heading, list item, or cell, and its text is all the editor changes. Tables, figures, captions, numbering, and formatting are the Agent's work, and rich-block editing requires a Host protocol addition rather than a private client DTO.
- The browser never maintains Markdown or complete editable HTML as a second body. Preview HTML is a derived projection; every durable body change is applied to the Working DOCX through `commit`.
- The Host owns preview generation and sanitization. The browser additionally strips active content and confines the document's stylesheet to a shadow tree, but it is not the document sanitizer.
- Blocks are paired with semantic nodes by their text: a block the Host projects as non-editable, or whose text the projection does not carry, stays read-only in place and points the user to the Agent.
