# @paperai/agent-acp

English | [中文](README.zh.md)

PaperAI exposes Codex and Claude through exact contributed preset routes. The native DSH factory remains available to other profiles. ACP model, reasoning, and switch selection uses the existing model picker; generic negotiated options and model favorites use the ACP session controls. Changes validate advertised values before RPC, apply model before dependent options, and restore the previous selection on rejection. Observers receive the settled selection. A failed restoration marks the runtime for rebuilding. Applied options are durable paperai/acp/config events; each request header carries the actual model and effort. Manual model IDs require provider acceptance.

`diagnosticStatus()` discovers adapter installation and reads cached model metadata without spawning. `probe()` runs an independent initialization in an empty temporary directory, with no prompt or PaperAI MCP descriptor, denied file callbacks, and native read-only mode. Concurrent probes for the same launch configuration share work. `Config.probeTimeoutMs` defaults to `15000`; `failureCooldownMs` defaults to `120000`; both must be positive integers. An explicit forced retry bypasses the failure cooldown. Real session startup also records metadata; an older probe cannot replace a newer observation. Cached model names never authorize live selection, and successful initialization does not prove a later prompt can authenticate. Disposal aborts probes and awaits their process-tree cleanup.

Each returned handle owns its published Agent, DSH Session, and local ACP process. Disposal waits for all three to reach quiescence, and failed startup rolls the unpublished lifecycle back so the same session ID can be retried. Immediately before dispatching an ACP prompt, the Agent rechecks the turn signal after resolving every prompt block, so cancellation cannot start new provider work. Once dispatched, prompt requests and established provider processes are not bound to the DSH turn signal. Cancellation sends ACP `session/cancel` and retires the operation generation that gates mode requests and file callbacks, but the DSH turn remains open until the provider sends its final prompt response; session updates already ordered before that response, including terminal tool updates, are projected before the step and turn close. The next runtime-bound operation closes the old process and resumes the provider session in a fresh process before accepting mode or file operations. Provider model discovery and selection share a FIFO queue, so only the queue head can own replacement maintenance while later operations continue against the recovered runtime. Pending turns remain reserved until the queue drains, and disposal closes the queue to new work before awaiting every admitted operation.

The DSH Session sandbox preset also selects the provider's advertised native ACP permission mode. Native `mode` and permission options remain read-only in the general ACP option editor. Codex maps `read-only`, `workspace-write`, and `danger-full-access` to `read-only`, `agent`, and `agent-full-access`; Claude maps them to `plan`, `acceptEdits`, and `bypassPermissions`. Claude's `acceptEdits` controls the provider's native file-edit posture; DSH still applies the `workspace-write` fence at every ACP client file callback. Codex receives the same target through `INITIAL_AGENT_MODE` at process startup. New and loaded sessions reconcile their advertised current mode before publication. A `/permission` switch first applies the target through ACP `session/set_mode`; only provider acceptance lets the preset, sandbox, and approval events become durable. Rejection therefore leaves the Session projection at its previous preset and fails the command. A switch during an active provider turn reserves maintenance before cancellation, drains that turn, and starts or synchronizes the replacement runtime in the target mode before committing the DSH events. The reservation defers every queued wake across the intermediate idle state; queued input resumes only after commit or failure, and a concurrent permission switch fails without releasing the active reservation. Direct non-command sandbox events retain the reconciliation observer, and the next prompt waits for its queued mode selection. Mode requests combine the Agent lifecycle, process generation, and caller cancellation signals, so a stalled provider request cannot continue to pin shutdown or a replacement prompt after a failed synchronization retires its generation. Startup or synchronization fails if the pinned adapter does not advertise the required native mode; the package does not invent provider mode identifiers or silently select a weaker mode.

An ACP adapter may return a session id before the provider has durable conversation history. If a cold `session/load` fails while the DSH Session contains neither `user/message` nor `turn/start`, the runtime creates a replacement provider session and records its new link. Once either event exists, load failure remains fatal: PaperAI never substitutes an empty provider session for conversation history it cannot restore.

ACP client file callbacks use the mounted DSH filesystem instead of Node filesystem calls. Reads retain the DSH read policy; every write resolves the current Session's sandbox mode and immutable Workspace root at the final filesystem operation. `read-only` rejects writes, `workspace-write` confines them to the Workspace and platform temporary roots, and Full access removes that fence. An ACP `session/request_permission` response does not implicitly widen a later file callback because ACP does not bind that grant to the subsequent `fs/write_text_file` request.

Every ACP session also owns one authenticated PaperAI MCP descriptor. The descriptor is supplied during ACP `session/new` or `session/load`, follows provider model changes for commit provenance, carries the session's workspace root and a live view of its sandbox mode so the MCP tools stay inside the session's own PaperAI project and refuse mutations under `read-only`, and is revoked with the Agent handle. Codex and Claude therefore use the same document commit, template gate, history, revert, and export services as the human workbench; a missing MCP service is a startup failure, never a silent fallback to filesystem-only editing.

Configure launch values under providers.codex and providers.claude; other identities are rejected. Top-level codex and claude settings remain readable and migrate into providers when writable settings attach. Canonical user fields take precedence; migration preserves credentials, removes the old keys, and refuses to overwrite a concurrent edit. Both formats redact secrets. Read-only storage or a failed migration keeps the legacy settings readable and reports a warning; subsequent changes to the registered settings section retry migration. Settings retain secrets through path edits and separately store models, favorites, generic options, personal instructions, and language. Launch changes apply to new runtime generations; display names and prompt preferences do not cancel startup, installation, or probing, or invalidate cached diagnostics. The Claude adapter uses its bundled Claude Code; providers.claude.env.CLAUDE_CODE_EXECUTABLE can select an installed executable, while providers.claude.command must remain an ACP adapter.

Channel defaults are preferences for new conversations. Custom model IDs are sent to the provider for validation; effort recognizes the thought_level category and the effort, reasoning_effort, and reasoning-effort IDs. Unavailable effort, switches, and generic options warn and retain the provider's current selection. Provider rejection is recoverable only after confirmed restoration; cancellation, connection loss, and failed restoration still reject startup. An explicit creation-time model overrides the stored default and retains strict selection. Resumed conversations retain their provider configuration.

The catalog's `connected` field reports whether a published conversation holds an open provider connection, independently of diagnostic results. Different conversations can use Codex and Claude concurrently. Startup reports stages and has a configurable deadline; newer selections and explicit cancellation retire pending startup. Optional authentication, logout, model-service configuration, history pagination, and deletion use advertised ACP capabilities. Imports stage replay into a new local conversation, deduplicate provider/host associations, and preserve existing drafts. Resume is preferred when advertised; load otherwise reconstructs context without duplicating the transcript. Native close precedes teardown. Local forks that cannot preserve the provider’s exact history are refused.

Provider commands appear as /acp-… and retain original arguments. Ordinary prompts include configured instructions and explicitly invoked local skills, logged as paperai/acp/context; native commands bypass that envelope. Form elicitation uses DSH questions and logs accepted responses. Filesystem and terminal callbacks log requests and returned results. Terminal processes have configurable count, output, and teardown limits. Tool progress coalesces output into bounded snapshots at Config.toolProgressIntervalMs (default 1000 ms). Status changes and turn completion flush immediately, including cancellation; history replay has no timer. Presenters reuse existing tool cards; text, reasoning, and message IDs preserve arrival order. Images use the attachment service; unsupported output media retains its original bytes in the log with a visible notice. Plans, titles, usage, stop reasons, and compaction state remain session observations.

Managed installations use private npm generations and publish a validated manifest atomically. Cancellation preserves the current installation; uninstall removes only its active managed generation. Older generations remain for processes that may still own them. SSH requires an explicitly configured POSIX host, Node, and installed adapter. Credentials travel through stdin with strict host-key checking; a private reverse tunnel forwards the revocable PaperAI HTTP MCP endpoint. Remote sessions receive no local filesystem or terminal callbacks. Local adapters without HTTP MCP use the existing MCP SDK’s stdio bridge.

Codex-owned terminal references and terminal_output_delta metadata feed the same bounded progress snapshots. Metadata must name the current tool call; malformed payloads and other call IDs are ignored. Client-owned terminals continue to use the terminal service.

## Model Experience

### Codex and Claude ACP sessions

#### What the model sees

The selected adapter receives user input, configured language and personal instructions, and explicitly invoked local skill text. Those additions and client replies are durable `paperai/acp/context` and `paperai/acp/client-request` events. @paperai/mcp owns the authenticated descriptor’s document tool schemas and results.

#### Token effect

User input, selected skills, configured instructions, client replies, and provider-owned context consume tokens. The MCP package owns its tool schema and result tokens; connection observations add none.

#### KV Cache effect

Each local ACP process owns provider request and cache reuse. Creating or loading a session, changing the selected provider model, or replacing the MCP descriptor can change subsequent request prefixes; this package does not retain or guarantee provider KV cache entries.

## Known Limitations and Deferred Work

- **Provider dependency** — The `codex` and `claude` routes require an ACP adapter and provider authentication, either bundled, privately installed, explicitly configured, or installed on a configured SSH host. Command startup or handshake failure rejects Agent creation. SSH requires a POSIX host with Node and HTTP MCP support; it does not synchronize local files.
- **Optional capabilities** — Authentication, service configuration, and history actions require provider-advertised support. Unsupported media keeps its source bytes in the session log and displays a notice; exact-context local forks remain unavailable.
- **Provider mode availability** — Full access requires the pinned adapter to advertise its native unrestricted mode. If the provider suppresses that mode in the current environment, selecting the DSH preset fails explicitly instead of leaving the two permission states inconsistent.
- **Cancellation settlement** — PaperAI waits for the provider's cancelled prompt response so protocol-ordered terminal updates remain in the turn. A non-conforming provider that never settles cancellation can delay quiescence.
- **Capability projection** — ACP Agents receive PaperAI document capabilities through the authenticated MCP descriptor. Native DSH Loop tools are not automatically mirrored into an ACP provider session.
- **Filesystem escalation** — ACP client file callbacks always enforce the Session's current sandbox preset. To permit an out-of-Workspace callback, the user must switch that Session to Full access through the standard DSH permission control; a preceding generic ACP approval does not create an unscoped filesystem grant.
